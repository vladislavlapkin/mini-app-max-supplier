# Проверенный поставщик — чат-бот и мини-приложение в MAX

Трек «Эффективный бизнес». Помогает закупщику малого и среднего бизнеса по обычному текстовому запросу получить
3–5 поставщиков товара. Показывает, почему компания попала в подборку, какие сведения о ней найдены, из какого
источника и на какую дату.

- **Бот:** https://max.ru/t711_hakaton_max_bot
- **Мини-приложение:** https://2-26-104-162.sslip.io (адрес `https://2016079.xorek.cloud` заработает, когда у домена появится DNS-запись)

Сервис **не** выставляет рейтинг надёжности и не гарантирует качество, наличие товара или исполнение договора.

## Назначение решения

Закупщику небольшой компании нужно быстро найти поставщика товара и понять, можно ли ему доверять. Сейчас это
часы ручной работы: поиск в интернете, проверка по реестрам, сравнение в таблице. Решение сводит это к диалогу
с ботом и короткой подборке в мини-приложении MAX:

- запрос пишется обычными словами, без ОКВЭД и регистрации;
- выдача ограничена 3–5 компаниями, у каждой есть блок «Почему в подборке»;
- у каждого факта указаны источник и дата проверки;
- подборку можно сравнить и сохранить без личного кабинета, по MAX ID.

## Основной пользовательский сценарий

1. Пользователь пишет боту: «Нужен производитель строительной краски в Московской области».
2. Бот распознаёт товар, регион, тип поставщика и, если они указаны, объём и требования к документам.
   Недостающее уточняет, не больше трёх вопросов (здесь спросит: «Ищем только производителя?»).
3. Пользователь подтверждает параметры. Бот сохраняет запрос под одноразовым `search_token` (15 минут)
   и присылает кнопку «Открыть подборку».
4. Открывается мини-приложение с уже заполненным поиском.
5. Отсев: убираются компании не из той товарной категории и с прекращённой деятельностью. По желанию
   включаются строгий регион, «только производитель», «только с документами», «ПП РФ №719».
6. Ранжирование: 70% веса — совпадение по товару, региону и типу поставщика, 30% — полнота и свежесть
   проверяемых сведений:
   `Score = 0.35·Товар + 0.20·Регион + 0.15·ТипПоставщика + 0.10·ЮрПроверка + 0.10·Документы + 0.05·ПолнотаПрофиля + 0.05·Свежесть`.
7. Пользователь получает до 5 карточек и открывает подробную: ОКВЭД, статус МСП, продукция и ГИСП,
   документы, что запросить у поставщика, финансы, риск-сигналы, контакты, источники.
8. Сравнивает до трёх поставщиков и сохраняет подборку. Бот присылает «Подборка сохранена», позже её
   можно открыть командой `/saved`.

Команды бота: `/start`, `/find`, `/saved`, `/help`, `/cancel`.

## Состав и архитектура

```
MAX (чат)  ──►  Бот (long polling или webhook) ──┐
                                                  ├─►  Search Service ─►  PostgreSQL (компании, факты, подборки)
MAX (мини-приложение, HTTPS) ─► API /api/* ──────┘         │
                                                           └─►  Redis (сессии бота, search_token, кэш, очередь)
```

Один контейнер `app` (Node.js 22, Fastify) обслуживает бота, API мини-приложения и отдаёт собранный фронтенд.

```
server/                 бэкенд на Node.js + TypeScript (Fastify)
  src/bot/              диалоговый движок: состояния, сессии в Redis, тексты, клавиатуры
  src/max/              клиент MAX Bot API, проверка initData, дедупликация событий
  src/parser/           разбор свободного запроса: товар, регион, объём, тип поставщика, документы
  src/search/           поиск, жёсткие фильтры, ранжирование, объяснение выдачи
  src/sources/          адаптеры источников с единым интерфейсом: retry, circuit breaker, кэш
  src/opendata/         импорт официальных открытых данных ФНС
  src/services/         search_token, сохранённые подборки, аналитика, audit trail
  src/http/             webhook, API мини-приложения, авторизация, rate limiting
  migrations/           схема PostgreSQL
  certs/                сертификаты Минцифры для TLS к platform-api2.max.ru
  test/                 unit-, contract- и E2E-тесты
webapp/                 мини-приложение: React 18 + TypeScript + Vite, zustand, react-router
data/catalog.json       товарная вертикаль: категории, синонимы, регионы, единицы, требования к документам
data/suppliers.json     ручная тестовая база: 63 вымышленные компании
db/init/                выгрузка реальных данных ФНС, загружается в PostgreSQL при первом старте
deploy/Caddyfile        HTTPS-прокси для сервера
docker-compose.yml      все локальные компоненты: app, postgres, redis
docker-compose.prod.yml добавляет Caddy (HTTPS, порты 80/443) для сервера
```

## Запуск одной командой

Нужен только Docker с Compose v2. Node.js локально не нужен.

```bash
cp .env.example .env
docker compose up -d --build
```

Откройте http://localhost:8080. В обычном браузере мини-приложение работает без MAX (`ALLOW_BROWSER_DEMO=true`).

- При первом запуске PostgreSQL сам загружает реальные данные ФНС из `db/init/` (4 339 компаний), а сервер
  применяет миграции и добавляет тестовую базу.
- Сборка образа занимает 2–3 минуты без учёта первой загрузки базовых образов.
- Чтобы заработал бот, впишите в `.env` токен `MAX_BOT_TOKEN` и поставьте `MAX_UPDATES_MODE=polling`.
  **Один токен — один запущенный сервер:** иначе два сервера будут перехватывать сообщения друг у друга.

## Параметры и переменные окружения

Все переменные задаются в `.env` (образец — `.env.example`, без токенов и паролей).

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `MAX_BOT_TOKEN` | — | Токен бота с платформы MAX для партнёров. Без него бот выключен, мини-приложение работает |
| `MAX_BOT_USERNAME` | из `GET /me` | Username бота для ссылки `https://max.ru/<username>?startapp=...` |
| `MAX_UPDATES_MODE` | `polling` | `polling` — long polling, `webhook` — продакшен с HTTPS, `off` — бот выключен |
| `PUBLIC_BASE_URL` | — | Публичный HTTPS-адрес сервера (нужен для webhook) |
| `MAX_WEBHOOK_SECRET` | — | Секрет webhook: символы `A-Z a-z 0-9 _ -`, 5–256 символов |
| `MAX_OPEN_APP_BUTTON` | `link` | Кнопка открытия подборки: `link` (deep link) или `open_app` |
| `PORT` | `8080` | Порт HTTP-сервера внутри контейнера |
| `LOG_LEVEL` | `info` | Уровень логов pino |
| `ALLOW_BROWSER_DEMO` | `true` | Разрешить мини-приложение в обычном браузере. `false` — только запросы с подписанным `initData` из MAX |
| `INIT_DATA_MAX_AGE_SEC` | `86400` | Сколько секунд действительна подпись `initData` |
| `SEED_ON_START` | `true` | Загружать ручную тестовую базу при старте |
| `DEMO_TRUST_MANUAL_DATA` | `true` | Учитывать документы тестовой базы в фильтре «Нужны документы» |
| `SEARCH_DATA` | `real` | `real` — реальные данные ФНС, `test` — тестовая база, `all` — обе |
| `SIMULATE_SOURCE_FAILURES` | — | Имитация отказа источников, например `FSA_DECL,SME_REGISTRY` |
| `SEARCH_TOKEN_TTL_SEC` | `900` | Время жизни ссылки на подборку из бота |
| `DATA_RETENTION_DAYS` | `180` | Срок хранения истории поиска, аналитики и audit trail |
| `RATE_LIMIT_PER_MIN` | `120` | Лимит запросов к API с одного пользователя в минуту |
| `ADMIN_TOKEN` | — | Токен для `/metrics` и `/admin/metrics` (не короче 16 символов) |
| `POSTGRES_PASSWORD` | `supplier` | Пароль PostgreSQL |
| `OPENDATA_REGIONS` | — | Регионы для импорта реестра МСП через запятую, пусто — вся Россия |
| `GISP_API_BASE`, `GISP_JWT`, `GISP_PRODUCTS_PATH`, `GISP_PP719_PATH` | — | Доступ к витринам ГИСП, выдаётся по заявке организации |
| `DOMAINS` | — | Только для сервера: домены для HTTPS через запятую |

Compose задаёт сам: `DATABASE_URL`, `REDIS_URL`, `OPENDATA_DIR`. В образе заданы `DATA_DIR`, `MIGRATIONS_DIR`,
`WEBAPP_DIST`, `NODE_EXTRA_CA_CERTS`.

## Внешние сервисы и интеграции

| Сервис | Зачем | Можно ли воспроизвести в Docker |
|---|---|---|
| **MAX Bot API** (`platform-api2.max.ru`) | приём сообщений, отправка ответов и кнопок | Нет, это внешняя платформа. Нужен токен бота. Без токена решение проверяется через мини-приложение в браузере |
| **MAX Bridge** (`st.max.ru/js/max-web-app.js`) | запуск мини-приложения внутри MAX, кнопка «Назад», `initData` | Нет. Вне MAX приложение работает без него |
| **Открытые данные ФНС** (`file.nalog.ru/opendata`) | реестр МСП, численность, налоговые режимы, задолженность, отчётность | Не требуется: выгрузка уже в `db/init/`. Обновить можно командой импорта |
| **Реестр недобросовестных поставщиков ФАС** | риск-сигналы | Импорт готов (`node dist/opendata/cli.js rnp`), нужен российский IP |
| **ГИСП** (каталог и ПП РФ №719) | продукция и статус производителя | Клиент готов (`server/src/sources/gispClient.ts`), нужен доступ по заявке |

TLS: `platform-api2.max.ru` использует сертификат «Russian Trusted Root CA» Минцифры. Он лежит в
`server/certs/russian_trusted_ca.pem` и подключается через `NODE_EXTRA_CA_CERTS`.

Чтобы мини-приложение открывалось из бота, его адрес нужно указать на платформе MAX для партнёров:
Чат-боты → бот → Настройки → ссылка на мини-приложение.

## Работа с данными

По ТЗ автоматизированное получение данных допускается только через официальный API, открытый набор данных,
разрешённую выгрузку или договор. Скрейпинг интерфейсов реестров запрещён. Поэтому реальные сведения берутся
из официальных открытых наборов ФНС:

| Набор | Что даёт | Дата набора в выгрузке |
|---|---|---|
| Единый реестр субъектов МСП | ИНН, ОГРН, название, регион, ОКВЭД, категория МСП, заявленная продукция | 10.09.2026 |
| Среднесписочная численность | численность | 25.09.2026 |
| Специальные налоговые режимы | УСН / АУСН / ЕСХН / ОСН | 25.09.2026 |
| Задолженность по налогам | сумма недоимки, пеней и штрафов | 25.09.2026 |
| Доходы и расходы по бухотчётности | доходы и расходы за прошлый год | 25.09.2026 |

Импорт отбирает компании шести категорий стройматериалов по основному ОКВЭД и по продукции, которую компания
сама указала в реестре МСП: 4 339 компаний по всей России из 6,76 млн записей реестра.

- `db/init/01-supplier-data.sql.gz` — выгрузка PostgreSQL после импорта. Содержит только данные о компаниях,
  без истории поиска, аналитики и сохранённых подборок. Загружается автоматически, когда том `pgdata` пуст.
- Обновить данные до свежих наборов (скачивается ~2,4 ГБ): `docker compose run --rm app node dist/opendata/cli.js all`.
- Как это отражено в продукте, без выдумывания фактов:
  - **Тип поставщика.** По одному ОКВЭД производитель не определяется: такие компании получают «Тип не определён».
    «Производитель (заявлено компанией)» — только если компания указала производимую продукцию в реестре МСП.
  - **Статус деятельности** «Действует» ставится по факту включения в реестр МСП на дату набора.
  - Для реальных компаний ЕГРЮЛ, ГИСП, Росаккредитация, РНП и ЕФРСБ помечены «не подключён», а не
    «записей не найдено».
- Сохранённые подборки и история поиска хранятся в PostgreSQL по MAX ID пользователя, `DATA_RETENTION_DAYS` дней.
- Логи — структурированный JSON. Токены, `initData`, телефоны и email в них маскируются.

## Тестовые данные

- `data/suppliers.json` — 63 **вымышленные** компании. ИНН и ОГРН начинаются с несуществующего кода региона «00»,
  записи помечены `MANUAL_TEST_DATA`, в интерфейсе у них бейдж «тестовые данные».
- Загружаются при каждом старте (`SEED_ON_START=true`) и обновляют сами себя, реальные данные не затрагивают.
- Показать только тестовую базу: `SEARCH_DATA=test`, обе базы: `SEARCH_DATA=all`, затем `docker compose up -d`.
- В тестовой базе есть производители, дистрибьюторы, документы, записи ГИСП и риск-сигналы — на них видна работа
  всех фильтров.
- Имитация отказа источника: `SIMULATE_SOURCE_FAILURES=FSA_DECL,SME_REGISTRY`. Поиск продолжит работать,
  в выдаче появится предупреждение «Часть сведений сейчас недоступна».
- Перегенерировать тестовую базу: `docker compose run --rm tools sh -c "cd server && npm ci && npm run gen:data"`.

## Пошаговый сценарий проверки

**В MAX (основной сценарий):**

1. Откройте https://max.ru/t711_hakaton_max_bot и нажмите «Начать» или отправьте `/start`.
2. Напишите: «Нужен производитель строительной краски в Московской области».
3. Бот уточнит: «Ищем только производителя?» — ответьте кнопкой.
4. Подтвердите параметры. Бот ответит числом найденных компаний и кнопкой «Открыть подборку».
5. В мини-приложении откроется выдача с заполненными параметрами: до 5 карточек с блоком «Почему в подборке».
6. Откройте карточку компании: ИНН и ОГРН, основание типа поставщика, источники с датами.
7. Нажмите «Сравнить» у двух-трёх компаний, затем «Сравнить» на плавающей панели.
8. Нажмите «Сохранить подборку». В чате придёт сообщение «Подборка сохранена», команда `/saved` покажет её.

**Локально, без MAX:**

1. `docker compose up -d --build`, дождитесь `docker compose ps` со статусом `healthy` у всех сервисов.
2. `curl http://localhost:8080/readyz` → `{"ok":true}`.
3. Откройте http://localhost:8080 → категория «Лакокрасочные материалы» → регион «Московская область» → «Найти».
4. Проверьте фильтры в выдаче, карточку компании, сравнение и сохранение.

Автотесты: `docker compose run --rm tools sh -c "cd server && npm ci && npm test"`,
E2E (нужны postgres и redis): `docker compose run --rm -e E2E=1 tools sh -c "cd server && npm run test:e2e"`.

## Известные ограничения

- Одна товарная вертикаль: шесть категорий стройматериалов.
- Для реальных компаний не подключены ЕГРЮЛ, ГИСП, Росаккредитация, РНП и ЕФРСБ: у бесплатных официальных
  источников нет API или доступ выдаётся по заявке. Поэтому статус производителя, документы и риск-сигналы у реальных
  компаний не подтверждены, о чём интерфейс прямо пишет.
- Тип «Производитель (заявлено компанией)» есть только у 12 реальных компаний, у остальных «Тип не определён».
  Фильтр «Только производитель» на реальных данных почти никого не отсекает, полностью он работает на тестовой базе.
- Регион по умолчанию не отсекает компании, а поднимает местные наверх. Строгий регион включается отдельно.
- Выдача — до 5 компаний. При равном балле порядок определяется по названию.
- Данные ФНС обновляются вручную командой импорта (реестр МСП обновляется 10-го числа каждого месяца).
- Мини-приложение в MAX открывается только по HTTPS.
- На стенде оставлен вход из браузера (`ALLOW_BROWSER_DEMO=true`), чтобы решение можно было проверить без MAX.
  В строгом режиме поставьте `false`.

## Остановка и повторный запуск

```bash
docker compose stop            # остановить, данные сохраняются
docker compose start           # запустить снова
docker compose up -d --build   # пересобрать после изменений в коде
docker compose logs -f app     # логи приложения
docker compose down            # удалить контейнеры, данные в томах сохраняются
docker compose down -v         # удалить и данные; при следующем запуске база загрузится из db/init заново
```

На сервере те же команды с оверлеем: `docker compose -f docker-compose.yml -f docker-compose.prod.yml <команда>`.

Резервная копия базы: `docker compose run --rm backup` (файл появится в `./backups`).

## Развёртывание на сервере

Проверено на Ubuntu 22.04 (1 vCPU, 2 ГБ RAM).

```bash
apt-get update && apt-get install -y docker.io docker-compose-v2 git
git clone https://github.com/vladislavlapkin/mini-app-max-supplier.git && cd mini-app-max-supplier
cp .env.example .env   # вписать MAX_BOT_TOKEN, MAX_UPDATES_MODE=polling, DOMAINS
docker compose -f docker-compose.yml -f docker-compose.prod.yml up -d --build
```

Caddy сам выпустит сертификаты Let's Encrypt для адресов из `DOMAINS`, если они указывают на сервер и открыты
порты 80 и 443. Затем укажите HTTPS-адрес мини-приложения в настройках бота на платформе MAX.

Эксплуатация: `GET /healthz` и `GET /readyz` — живость и готовность, `GET /metrics` — метрики Prometheus,
`GET /admin/metrics?days=30` — метрики успешности поиска (оба с заголовком `X-Admin-Token`),
`GET /api/sources/health` — состояние источников.
